# Technical route

> 当前 Stage D 已经完成了一个能够自动运行的最小闭环：  
> **感知枝条 → 建立几何模型 → 计算切割姿态 → UAV–机械臂协同接近 → 完成切割 → 安全撤退。**
>
> 接下来的重点，不再是继续堆叠状态机，而是在这个闭环基础上，逐步解决“看得清、选得对、够得着、切得安全”这几个更接近真实任务的问题。

---

## 1. 总体目标

后续系统希望从“给定一根可靠枝条后能够完成切割”，进一步发展为：

\[
\boxed{
\text{复杂环境感知}
\rightarrow
\text{目标选择}
\rightarrow
\text{可达性与安全评估}
\rightarrow
\text{CLEAR / CUT 决策}
\rightarrow
\text{轨迹执行}
\rightarrow
\text{重新感知与规划}
}
\]

最终形成一套面向复杂树冠和输电线路环境的 UAV–机械臂协同伐枝系统。

- 感知层负责树枝、树叶、输电线和局部环境建模；
- 决策层负责选枝、候选切割点和 CLEAR / CUT 判断；
- 运动规划层负责机械臂可达性、安全裕度和 UAV 重定位；
- 执行层继续沿用 PX4 Offboard、机械臂控制和链锯执行。

---

## 2. 两种作业 Primitive：CLEAR 与 CUT

后续不打算把“修叶”和“伐枝”做成两套独立系统，而是作为同一任务规划框架下的两种基本操作：

\[
\boxed{
\mathcal P=
\{
\text{CLEAR},
\text{CUT}
\}
}
\]

### CLEAR：修叶 / 清障

CLEAR 的目的不是单纯修剪叶片，而是**改善枝条的可见性和感知质量**。

例如：

```text
枝条模型置信度较低
↓
分析原因
↓
判断存在叶片遮挡
↓
执行 CLEAR
↓
重新扫描与建模
```

如果感知质量差并不是叶片遮挡造成的，也可以选择 UAV 重定位、重新扫描或继续融合，而不是直接执行 CLEAR。

### CUT：伐枝

当枝条模型可靠，并且候选切割点满足可达性和安全条件后，再进入 CUT。

因此任务逻辑可以逐步发展为：

```text
感知质量可靠吗？
├─ 否 → 分析原因 → CLEAR / UAV 重定位 / 重新感知
└─ 是 → 候选切割点 → 可达性与安全评估 → CUT
```

## 3. 枝条拓扑与“根部回溯”选枝

Stage C 当前主要针对单根枝条建立：

\[
\{\mathbf p_0,\mathbf d,L,r\}
\]

后续需要进一步建立局部树枝结构。

可以将树冠局部结构表示为图：

\[
\boxed{
G=(V,E)
}
\]

其中：

- \(V\)：枝梢、分叉点、候选切割点；
- \(E\)：枝条段；
- 每条枝条可以附带方向、直径、长度、危险程度等属性。

对于进入危险区域的枝梢，可以从枝梢开始沿骨架向根部回溯：

```text
枝梢
    ↓
沿枝条骨架向根部搜索
    ↓
经过多个分叉点
    ↓
生成候选切割位置
```

这样就不再只是“看到哪里切哪里”，而是根据树枝拓扑关系选择更合理的切除位置。

---

## 4. 候选切割点：从“能切”到“选哪个更合适”

对于候选切割点集合：

\[
\mathcal C=
\{c_1,c_2,\ldots,c_n\}
\]

希望在满足约束的条件下，选择收益最大的切割方案：

\[
\boxed{
c^*
=
\arg\max_{c\in\mathcal C}
U(c)
}
\]

这里的 \(U(c)\) 可以理解为“切掉这个位置以后，能够消除多少危险枝条或危险区域”。

但候选点首先必须满足基本约束，例如：

- 与输电线距离满足安全要求；
- 枝条直径不超过链锯能力；
- 属于目标危险区域；
- 机械臂可达、IK 有解；
- 链锯姿态能够实现；
- 周围空间允许机械臂和 UAV 作业；
- 不会在到达目标之前先碰到其他枝条；
- 当前枝条模型可信。

因此真正的问题不是“哪根树枝最大”，而是：

> **在所有安全、可达、可执行的候选方案中，选择最值得切的一处。**

---

## 5. 安全裕度 \(S\)

为了评价一个可行方案到底“有多安全”，后续可以引入安全裕度：

\[
S
\]

其中考虑：

- 关节限位余量；
- 是否远离奇异位形；
- UAV、机械臂与树体的距离；
- 与输电线的安全距离；
- 机械臂伸展程度；
- 切割姿态是否合理；
- 感知模型可信度。

这里建议分成两层。

第一层是**硬约束**：

```text
IK 无解
碰撞
超过关节限位
距离输电线过近
```

出现这些情况直接判定为不可执行。

第二层是在已经可行的方案中，再用 \(S\) 比较安全余量：

\[
\boxed{
S\geq S_{\min}
}
\]

只有满足最低安全要求的方案才进入执行。

这样可以避免“某一项已经非常危险，但因为其他指标很好，最后平均分仍然很高”的问题。

## 6. 待移植框架

后续准备引入的框架不会替换现有系统，而是分别负责不同部分。

### 感知：Open3D / PCL
> [Open3D: A Modern Library for 3D Data Processing](https://github.com/isl-org/Open3D)
> [Point Cloud Library (PCL)](https://github.com/PointCloudLibrary/pcl)

Open3D 可以优先用于：

```text
DBSCAN
体素降采样
离群点过滤
法向估计
局部点云聚类
```

PCL 后续可用于更复杂的 RANSAC、圆柱拟合、法向与几何分割等。

### 机械臂：MoveIt 2
> [🤖 MoveIt for ROS 2](https://github.com/moveit/moveit2)

MoveIt 2 主要用于：

```text
碰撞检测
Planning Scene
机械臂轨迹规划
约束运动规划
```

把当前“某个姿态理论上可达”进一步升级为“机械臂可以安全地运动到这个姿态”。

### 运动学：Orocos KDL / pick_ik

KDL 继续负责基础 FK、Jacobian、IK 等运动学计算。

如果后续普通 IK 难以处理多解或复杂约束，再考虑接入 pick_ik。

### UAV：PX4 Offboard

Offboard 继续负责 UAV 的位置与 yaw 控制，并在目标不可达或视角不佳时执行主动重定位。

## 7. 后续工作阶段划分

为了避免一次性把系统复杂度拉得过高，后续建议分阶段推进。

### Stage E：复杂枝条感知与局部树结构

重点：

```text
点云清理
复杂树枝建模
骨架提取
分叉关系
Branch Graph
感知置信度
```

目标是从“单根枝条模型”升级到“局部树结构模型”。

### Stage F：候选切割点与任务决策

重点：

```text
根部回溯
候选切割点生成
危险区域判断
CLEAR / CUT 决策
约束条件下的最优目标选择
```

输出从“枝条模型”进一步变成“推荐切割点”。

### Stage G：MoveIt 2 与安全可达性

重点：

```text
机械臂可达性
碰撞检测
Planning Scene
IK
安全裕度 S
```

解决“算得出来”和“能安全到达”之间的差别。

### Stage H：主动重定位与完整闭环

最终形成：

```text
感知质量差
→ CLEAR / UAV 重定位
→ 重新感知

目标不可达
→ UAV 重定位
→ 重新 IK 与安全评估

目标可行
→ CUT
→ 更新地图
→ 继续下一目标
```

实现真正意义上的闭环自主作业。

---

## 8. 总结

当前 Stage D 已经解决：

> **给定一根可靠枝条以后，UAV–机械臂能不能完成一次自主切割。**

后续工作的核心则逐步转向：

> **应该切哪根、从哪里切、看不清怎么办、够不到怎么办，以及怎样判断当前方案是否足够安全。**

因此整体研究路线可以概括为：

\[
\boxed{
\text{感知}
\rightarrow
\text{理解}
\rightarrow
\text{选择}
\rightarrow
\text{评估}
\rightarrow
\text{执行}
\rightarrow
\text{重新感知}
}
\]

这条路线既保留了现有 Stage D 的最小闭环，又为后续感知、决策、规划和安全评价提供了清晰的升级方向。
