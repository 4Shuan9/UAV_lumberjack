# Step13 机械臂运动学交接说明

> 项目：UAV Lumberjack 空中伐枝系统  
> 用途：提供给负责 Step13 机械臂 D-H 参数建模、正运动学（FK）、逆运动学（IK）的同学  
> 当前基线：Step12 最终仿真模型 + 当前 `arm_controller.cpp` 角度映射  
> 说明：本文重点给出**当前仿真中已经确定的机械结构、坐标关系、关节定义、角度映射和控制参数**。运动学推导应尽量以这些定义为准，避免另外重定义角度零点后与 Gazebo/控制器不一致。

---

## 1. 当前机械臂总体结构

当前机械臂为 3 自由度：

```text
UAV base_link
    ↓
arm_base
    ↓
yaw_link（固定肩部安装座，名称为历史遗留）
    ↓
J2：肩关节 Pitch
    ↓
upper_arm
    ↓
J3：肘关节 Pitch
    ↓
forearm
    ↓
J4：腕部 Roll
    ↓
wrist_link
    ↓
chainsaw_body
    ↓
链锯切割区域
```

### 重要说明

原机械臂 J1 已取消。

当前系统中：

```text
机械臂水平朝向
→ 由 UAV yaw 完成
```

因此机械臂本体只保留：

\[
q=[q_2,q_3,q_4]^T
\]

其中：

- `J2`：肩关节俯仰
- `J3`：肘关节俯仰
- `J4`：腕部滚转

如果后续做 UAV–机械臂协同规划，可将 UAV yaw 作为额外变量：

\[
q_{task}=[\psi_{UAV},q_2,q_3,q_4]^T
\]

但 Step13 机械臂 FK/IK 可先只处理 `J2/J3/J4`。

# 2. 建议使用的参考坐标系

建议最终机械臂运动学输出统一相对于：

```text
base_link
```

当前 UAV / ROS 坐标约定：

```text
+X：UAV 前方
+Y：横向
+Z：竖直向上
```

J2 和 J3 的关节轴均为：

```text
0 -1 0
```

即绕局部 `-Y` 轴转动，因此主要运动位于：

```text
X-Z 平面
```

J4 轴为：

```text
1 0 0
```

即绕腕部/前臂自身 X 轴滚转。

> 如果采用标准 DH / 改进 DH，DH 坐标系中的 z 轴应按 DH 规则重新沿关节轴建立，不要直接把 Gazebo 的全局 XYZ 当作 DH 坐标轴。

# 5. Gazebo 中 HOME 姿态的 Link Pose

这一部分非常重要。

当前模型采用了：

> **Gazebo raw joint angle = 0 时，机械臂物理外形已经处于 HOME 姿态。**

因此 SDF 中部分 link pose 已经“烘焙”了 HOME 姿态角。

## 5.1 upper_arm 相对 yaw_link

```text
position = [0.077942, 0, -0.075000] m
RPY      = [0, 0.523599, 0] rad
```

即 pitch：

```text
+30°
```

该固定 pose 与 J2 的 `-Y` 轴定义共同形成 logical J2 = `-30°` 的 HOME 外形。

---

## 5.2 forearm 相对 upper_arm

```text
position = [0.016388, 0, -0.042500] m
RPY      = [0, 2.617994, 0] rad
```

即 pitch：

```text
+150°
```

该 pose 对应当前模型 HOME 状态下 J3 logical = `-150°` 的物理外形。

---

## 5.3 wrist_link 相对 forearm

```text
position = [0.110, 0, 0] m
RPY      = [-1.570796, 0, 0] rad
```

注意：

J4 joint 本身位于 forearm：

```text
[0.085, 0, 0] m
```

因此 wrist_link 的中心比 J4 joint origin 沿前臂轴继续向外约：

```text
25 mm
```

### 当前没有单独定义一个显式 `tcp_link`

因此正式 FK/IK 前，应明确一个统一 TCP。

1. `chainsaw_body` 原点作为末端参考点，再额外定义切割偏置；
2. 新增一个仅用于运动学的虚拟 TCP frame，例如：

```text

```

推荐方式 2，更利于后续 ROS TF、IK 和切割任务规划。

> 建议不要通过改变物理模型位置来“凑”TCP，只添加固定参考 frame 即可。

# 9. 最重要：Logical Angle 与 Gazebo Raw Angle 映射

运动学推导建议全部采用 **logical angle**：

\[
q_2,q_3,q_4
\]

不要直接把 Gazebo `/joint_states` 的 raw angle 当成 DH 角度。

当前定义：

```text
HOME：
J2 = -30°
J3 = -150°
J4 = -90°
```

Gazebo raw joint = 0 时即为上述 HOME 姿态。

因此：

\[
q_{logical}=q_{raw}+q_{offset}
\]

其中：

\[
q_{2,offset}=-30^\circ
\]

\[
q_{3,offset}=-150^\circ
\]

\[
q_{4,offset}=-90^\circ
\]

也就是：

\[
q_{2,raw}=q_2+30^\circ
\]

\[
q_{3,raw}=q_3+150^\circ
\]

\[
q_{4,raw}=q_4+90^\circ
\]

---

# 10. Logical 关节范围

控制器对外使用的实际逻辑范围为：

| Joint | Logical min | Logical max |
|---|---:|---:|
| J2 | -165° | +15° |
| J3 | -150° | +150° |
| J4 | -180° | +180° |

因此 IK 最终候选解必须满足：

\[
-165^\circ\le q_2\le15^\circ
\]

\[
-150^\circ\le q_3\le150^\circ
\]

\[
-180^\circ\le q_4\le180^\circ
\]

> 不要直接使用 SDF raw joint limit 作为最终 IK logical limit。

# 14. ROS2 / Gazebo 关节话题

ROS2 关节命令：

```text
/lumberjack_arm/j2/cmd_pos
/lumberjack_arm/j3/cmd_pos
/lumberjack_arm/j4/cmd_pos
```

Gazebo 对应：

```text
/model/x500_lumberjack/joint/j2/0/cmd_pos
/model/x500_lumberjack/joint/j3/0/cmd_pos
/model/x500_lumberjack/joint/j4/0/cmd_pos
```

关节状态：

```text
/lumberjack_arm/joint_states
```

包含：

```text
j2
j3
j4
saw_spin_joint
```

### 重要

`/lumberjack_arm/joint_states` 中的 J2/J3/J4 是 **Gazebo raw radians**。

如果 Step13 新写 FK 验证节点直接订阅该 topic，必须先转换为 logical angle：

```text
q2_logical_deg = q2_raw_rad × 180/pi - 30
q3_logical_deg = q3_raw_rad × 180/pi - 150
q4_logical_deg = q4_raw_rad × 180/pi - 90
```

再转换为 rad 用于运动学计算：

\[
q_{logical,rad}=q_{logical,deg}\frac{\pi}{180}
\]

不要直接将 raw rad 代入以 logical zero 定义的 DH/FK 模型。

# 19. 最容易出错的几个地方

## ① 把 Gazebo raw angle 当成 logical angle

这是最重要的坑。

正确关系：

```text
logical = raw + offset
```

---

## ② 直接照抄 SDF child link pose 当作 DH 角

当前模型的 link pose 已经把 HOME 外形烘焙进去。

因此需要区分：

```text
固定几何偏置
vs
关节变量
```

---

## ③ 忽略 J4 后面的腕部和链锯固定偏置

若只算到 J4 joint origin，得到的不是最终切割 TCP。

---

## ④ 没有统一 TCP

在开始最终 IK 前，应先明确 `chainsaw_tcp` 的定义。

---

## ⑤ 标准 DH 和 Modified DH 混用

一旦选定 DH convention，参数表和变换矩阵公式必须使用同一 convention。
